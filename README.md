# classroom-rotation-scheduler

[![test](https://github.com/2448309821/classroom-rotation-scheduler/actions/workflows/test.yml/badge.svg)](https://github.com/2448309821/classroom-rotation-scheduler/actions/workflows/test.yml)

日本語教室のボランティア講師の出席回答から、毎月の担当表を作る割り当てロジックです。
教室で運用しているWebシステム「教室シフト」から、割り当て処理と単体テストだけを抜き出して公開しています。

- デモ（ブラウザで動かせます）：https://2448309821.github.io/classroom-rotation-scheduler/
- 紹介ページ：https://2448309821.github.io/intro-page/projects/wawon.html
- 画面（React）、共有データの保存（Supabase）、運用データはこのリポジトリに含めていません。
- 講師名とクラス名は架空の名前（講師A〜H、入門(分割A/B) など）に置き換えています。

## 動かし方

Node.js 18以降で、追加のパッケージなしで動きます。

```bash
npm test          # 単体テスト（12件）
npm run example   # 架空の回答から1か月分の担当表を表示
```

## 割り当ての考え方（`src/schedule.js`）

その日に出席できる講師から、担当できるクラスの条件を満たす組み合わせを全通り作り、評価の配列を先頭から順に比べて最も良いものを選びます。クラス数・講師数が少ないため、全通りを比べても一瞬で終わる規模です。

評価の順番（`scoreAssignment`）：

1. 月の担当上限の超過が少ない
2. 前回と同じクラスへの連続担当が少ない（※）
3. 同じクラスへの偏りが少ない（※）
4. その月の担当回数が少ない
5. 例会の日は遠方の講師を優先する
6. 例会を休みたい講師は、例会の日に避ける
7. 最後は登録順

※ 2と3は、管理者が「同じクラスの連続担当・偏りを避ける」（`avoidRepeatedClasses`）を有効にしたときだけ数えます。無効のときは常に0です。

△（人数が足りなければ担当）の講師は、○の講師だけで埋まらないときに優先順に一人ずつ加えます。それでも埋まらないクラスは「人数不足のため未定」として管理者に知らせます。管理者が「ランダム」を選んだときは、最も良い候補が複数あればシード付きの乱数で一つを選び、同じシードなら同じ結果になります。

`src/lockedAssignments.js` は、確定済みの過去の担当表（Markdownの表）から割り当てを復元し、あとから手動で入れ替えた担当を上書きする処理です。

## 設計メモ

- **日ごとに順番に決める**：月全体を一度に最適化するのではなく、土曜日ごとに前から順に決め、それまでの担当回数・前回の担当を次の日の評価に使います。管理者が手動で固定した担当は先に反映し、残りのクラスだけを自動で決めます。
- **重み付きの合計ではなく、配列を先頭から比べる**：上位の条件（月の上限超過など）は、下位の条件をいくら積み上げても覆りません。重みの調整が要らず、なぜその案が選ばれたかを順番どおりに説明できます。
- **全通りを比べる**：候補の数は1日あたり「講師数からクラス数を選ぶ組み合わせ × クラスへの並べ方」です。講師8名・クラス5つでも 56 × 120 = 6,720 通りで、ブラウザでも一瞬で終わる規模のため、近似の探索は使っていません。
- **月の上限は二段階**：まず上限内の講師だけで割り当てを試し、埋まらないときだけ上限を超える案も含めて探し、超過した講師は「月上限超過」として表示します。

## テストで確かめていること（`src/*.test.js`）

- 月の担当上限に達した講師は、ほかの講師で埋められる限り再び割り当てない
- △の講師は、○の講師だけで埋まらないときだけ優先順に加える
- 誰も担当できないクラスは「人数不足のため未定」として残す
- 例会の日は遠方の講師を優先する
- 前回と同じクラスへの連続担当を避け、ほかに選択肢がなければ許す
- 手動で固定した講師に、自動で2つ目のクラスを割り当てない
- 同じシードなら同じランダム割り当てになる
- 分割週は入門クラスを2つに分け、休講日は割り当てない
- 過去の担当表（Markdown）から割り当てを復元し、手動の入れ替えで上書きする

12件のうち6件は運用中のコードにあったテストで、残りの6件はこのリポジトリを公開するときに、説明している仕様を確かめるために追加しました。GitHub Actionsで、push のたびにテストと例の実行を確認しています。
